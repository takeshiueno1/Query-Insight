# 55名リアリティデータ

## 目的と適用範囲

ローカル環境で社員検索、組織・上長スコープ、評価、タレントプロフィール、AI育成助言を一連で検証するための架空データである。`local` Spring Profileでのみ生成され、実在する人物・企業・顧客の情報は含まない。本番環境でこのシード処理は実行されない。

## データ規模

| 項目 | 件数・構成 |
| --- | --- |
| 社員・アカウント | リアリティデータ55名＋簡易動作確認1名、合計56アカウント |
| 組織 | 1本部、7部門 |
| 評価 | 56対象、上長評価は1人6軸。複数の状態例を含む |
| スキル | 28マスタ、1人5件、合計280保有情報 |
| 得意分野 | 内部型`KNOWLEDGE`の10マスタ、1人3件、合計168保有情報 |
| 業務経歴 | 1人1～2件。役割、期間、成果、利用技術を保持 |
| 資格 | 8マスタ、1人1件、確認済み状態 |

部門はプロダクト開発、データプラットフォーム、プロダクト企画、法人営業、カスタマーサクセス、人事・組織開発、経営管理で構成する。部門長・マネージャー・メンバーの上長関係を設定している。

## ローカルアカウント

既存の代表アカウントに加え、`QI0006`～`QI0055` は社員番号を小文字にしたログインIDを使用する。`QI0051` は役職者で、`QI0052`～`QI0055` の直属上長として登録する。

```text
例: QI0025 → qi0025@query.local
共通ローカルパスワード: QueryInsight2026

簡易動作確認専用アカウントはログインID `ueno`、パスワード `5050Rock` とする。このアカウントは
`local` プロファイルでだけ作成され、本番環境には作成しない。
```

共通パスワードと架空ドメインはローカル検証専用である。外部公開環境や本番環境へ転用してはならない。

## AI分析へ渡す情報

分析を実行した場合、次のうち承認済みまたは本人へ公開済みの情報だけを分析材料として使用する。Ollamaを利用できない場合のPROTOTYPEも同じ入力境界を使用する。

- 承認済みスキルと得意分野
- 承認済み業務経歴と資格
- 承認済み情報から算出した自己ステータス
- 本人へ公開済みの上長評価

氏名、社員番号、メールアドレス、ログインID、部署名・コード、DBの公開IDは送信しない。保存済みの自由記述は信頼できない入力として扱い、辞書・形式検査で識別情報を除去する。AI出力はランク判定や採用・解雇・昇進・配置・報酬等の人事判断に使用せず、該当表現を検出した結果は保存しない。

## 評価・自己ステータスの確認状態

- 本人の自己評価入力は廃止済みであり、簡易確認アカウントを含む現行の一般導線には表示しない。
- 自己ステータスは承認済みのスキル40％、得意分野20％、業務経歴25％、資格15％から自動算出し、本人編集不可である。
- 上長評価は直属上長が6軸をS/A/B/C/D/Fで保存・提出し、`OFFICER/ALL`の最終承認後だけ本人へ公開する。
- initializerは旧DB互換確認用の`SELF_RETURNED`を含み得る。現行サービスは上長保存で回復でき、新しい本人差戻しは作成しない。

## 再実行

シード処理は既存レコードをキーで確認してから不足分だけを追加する。従来のローカルDBを再利用した場合も55名のリアリティデータと簡易動作確認1名へ増補され、コンテナ再起動で重複しない。完全に作り直す場合のみ、DB削除の影響を確認してからDocker volumeを削除する。
