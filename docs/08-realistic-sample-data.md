# 50名リアリティデータ

## 目的と適用範囲

ローカル環境で社員検索、組織・上長スコープ、評価、タレントプロフィール、AI育成助言を一連で検証するための架空データである。`local` Spring Profileでのみ生成され、実在する人物・企業・顧客の情報は含まない。本番環境でこのシード処理は実行されない。

## データ規模

| 項目 | 件数・構成 |
| --- | --- |
| 社員・アカウント | 50名・50アカウント |
| 組織 | 1本部、7部門 |
| 評価 | 50対象、1人6軸、合計300明細 |
| スキル | 28マスタ、1人5件、合計250保有情報 |
| 専門知識 | 10マスタ、1人3件、合計150保有情報 |
| 業務経歴 | 1人1～2件。役割、期間、成果、利用技術を保持 |
| 資格 | 8マスタ、1人1件、確認済み状態 |

部門はプロダクト開発、データプラットフォーム、プロダクト企画、法人営業、カスタマーサクセス、人事・組織開発、経営管理で構成する。部門長・マネージャー・メンバーの上長関係を設定している。

## ローカルアカウント

既存の代表アカウントに加え、`QI0006`～`QI0050` は社員番号を小文字にしたログインIDを使用する。

```text
例: QI0025 → qi0025@query.local
共通ローカルパスワード: QueryInsight#2026
```

共通パスワードと架空ドメインはローカル検証専用である。外部公開環境や本番環境へ転用してはならない。

## AI分析へ渡す情報

AI分析を明示的に有効化した場合、次を分析材料として送信する。

- 評価期間
- 現在の役割と勤続年数
- 6能力軸のレベルと評価根拠
- 上位12件までのスキル名、レベル、経験年数、根拠
- 上位10件までの専門知識名、レベル、根拠
- 直近5件までの役割、業界、業務概要、成果、利用技術
- 確認済み資格名と発行元

氏名、社員番号、メールアドレス、DBの公開IDは送信しない。保存済みの自由記述は信頼できない入力として扱うようシステム指示を設定し、採用・解雇・報酬の自動決定には利用しない。

## 再実行

シード処理は既存レコードをキーで確認してから不足分だけを追加する。従来の5名入りローカルDBを再利用した場合も50名へ増補され、コンテナ再起動で重複しない。完全に作り直す場合のみ、DB削除の影響を確認してからDocker volumeを削除する。
