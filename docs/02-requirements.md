# 要件

状態は現在のMVPに対する実装状況を示す。`実装済み` はAPI・DB・UIが接続済み、`画面骨格` はルーティングと表示のみ、`互換用のみ` は現行の利用者導線から廃止済みだが既存データ・旧クライアント保護のため内部契約を残す状態、`未実装` は後続対象である。実ブラウザの視覚・操作確認は静的検証および実HTTP確認と分けて記録する。

## 自己ステータス算出契約

- スキル点と得意分野点は、正式反映済みの習熟度平均を `習熟度 / 5 × 100` で換算する。
- 業務経歴点は、重複月を二重加算しない承認済み経験月数を `min(経験月数 / 120 × 100, 100)` で換算する。
- 資格点は、取得日前でなく、有効期限未設定または算出日時点で有効な承認済み資格を1件20点、最大100点とする。
- 総合点は `スキル×0.40 + 得意分野×0.20 + 業務経歴×0.25 + 資格×0.15`。DB保存値は小数第2位まで、画面は小数第1位で表示し、ランクは丸め前の値で判定する。
- ランク境界はS 90以上、A 80以上、B 70以上、C 60以上、D 50以上、F 50未満とする。
- 算出元fingerprint、算出方式、算出日時をsnapshotへ保存し、同一入力の再計算は同じsnapshotへ収束させる。

## 上長評価契約

- 6軸ランクは内部計算時だけS=100、A=85、B=75、C=65、D=55、F=0へ変換し、等重み平均から総合ランクを算出する。
- 下書き保存でも6軸すべてのrank指定を必須とし、コメントと総評は提出時に必須とする。利用者画面へ変換後の数値scoreは公開しない。
- 上長入力は`DRAFT`を含む上長編集可能状態から開始できる。旧`SELF_RETURNED`行も上長保存で回復できる。
- 廃止済みの本人差戻しAPIは認証・scope・割当・versionを検査後、410 `SELF_EVALUATION_RETURN_RETIRED`で拒否し、新しい`SELF_RETURNED`を作らない。
- 最終承認前の上長評価は本人へ公開しない。本人用APIは`FINALIZED`だけを返し、それ以外は404とする。
- 版競合と同時初回保存の競合は409とし、状態遷移、版、workflow event、監査、通知を同じ業務トランザクションで扱う。

## データ要件

- APIには数値IDを公開せず、26文字ULIDを使用する。
- 社員番号、ログインID、スキルコード等は一意制約で二重登録を防ぐ。
- 評価基準、上長評価版、確定時点の自己ステータスsnapshotを保持し、後日の変更で過去結果を変えない。
- 更新競合が業務上問題になる社員・評価・申請データは `version` で楽観ロックする。
- 添付検査はPENDING/CLEAN/INFECTED/ERROR、試行回数、次回検査時刻を保持する。再検査claimは短いトランザクションと`FOR UPDATE SKIP LOCKED`を用い、scanner待機中にDB接続・行ロックを保持しない。
- 監査ログは業務データと分離し、利用者向けエラーと調査情報を分ける。

## 業務ルール

- ロールとデータスコープを別々に判定し、メニュー表示だけに認可を依存しない。
- 一般利用者は本人、上長は割当済み直属部下、全社役職者は`OFFICER/ALL`の範囲だけを操作する。`ADMIN`だけを理由に他社員のタレント・評価内容を公開しない。
- タレント申請と評価の状態遷移はサーバー側で検証する。
- 上長評価は全社役職者の最終承認後だけ社員本人へ公開する。
- 期限後も上長・全社役職者の操作を許可するが、期限超過を表示・履歴化する。
- 最終承認後は通常変更不可とし、`OFFICER/ALL`だけが理由付きで再オープンできる。
- 代理操作は許可しない。
- AI/PROTOTYPEは育成助言だけを返し、ランク、採用、解雇、昇進、配置、報酬等の人事判断を決定しない。

## 要件間の依存関係

認証・認可（FR-AUTH）が全機能の前提である。自己ステータス（FR-STATUS）は承認済みタレント情報、上長評価（FR-EVAL）は社員・評価対象・評価者割当・評価基準版に依存する。全社役職者の最終判断は`OFFICER/ALL`に依存する。AI分析（FR-AI）は承認済み情報、本人へ公開済み評価、識別情報除去、人事判断禁止、保存・監査に依存する。
