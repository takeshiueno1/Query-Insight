## 背景と目的

社員情報、スキル、資格、経歴、評価情報が分散し、検索・育成・配置判断で再利用しにくい課題を解決する。社員本人による更新と評価、上長による評価、管理者によるマスタ・期・権限管理を一つのシステムで扱い、変更履歴と監査可能性を確保する。

## 関係者

| アクター | 主な責務 |
| --- | --- |
| 社員 | 自身のプロフィール、スキル、資格、経歴の参照・更新、自己評価 |
| 上長・評価者 | 担当社員の参照、上長評価、コメント、差分確認 |
| 人事・管理者 | 社員・組織・アカウント・マスタ・評価期・評価基準の管理、監査 |
| システム運用者 | 稼働監視、バックアップ、障害対応、セキュリティ運用 |

## 前提と制約

- 社内向けWebアプリケーションで、PC中心のUIを想定する。
- Java 21 / Spring Boot 4.1系 / React 19.2系 / MySQL 8.4 LTSを採用する。
- APIは `/api/v1`、JSON、RFC 9457相当の `application/problem+json` を基本とする。
- 公開IDはULID、DB内部参照は数値IDを用いる。
- AI分析はデータ送信範囲、契約、保持条件が承認されるまで無効化する。

## 用語

| 用語 | 意味 |
| --- | --- |
| 評価期 | 自己評価・上長評価を実施する期間と締切を管理する単位 |
| 評価対象 | 評価期、対象社員、評価者の対応関係 |
| 評価基準バージョン | 評価項目、重み、グレード境界をある時点で固定した版 |
| データスコープ | 本人、直属配下、組織配下、全社など、ロールとは別の参照範囲 |
| 公開ID | APIや画面で使用する推測困難なULID |

## 外部依存

現時点で必須の外部SaaSは確定していない。メール配信、SSO、AIベンダー、クラウド運用基盤は未決事項であり、初期成果物はローカルMySQLだけで再現可能にしている。
